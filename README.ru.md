# Componenta Identity

UUID value objects и генераторы для доменных идентификаторов.

## Установка

```bash
composer require componenta/identity
```

Пакет объявляет `Componenta\Identity\ConfigProvider` в `extra.componenta.config-providers`.
Если установлен `componenta/composer-plugin`, провайдер автоматически добавляется в сгенерированный список провайдеров.

## Требования

- PHP 8.4+
- 64-bit PHP для `UuidFactory`
- `componenta/config ^3.0` для входящего в пакет `ConfigProvider`

## Связанные пакеты

| Пакет | Зачем нужен здесь |
|---|---|
| `componenta/policy` | Использует `IdentityInterface` для акторов и владельцев ресурсов. |
| `componenta/cqrs` | `Operation` генерирует UUID для идентификатора операции. |
| `componenta/di` | Регистрирует `UuidFactoryInterface` через `ConfigProvider`. |
| `componenta/uuid` | Необязательный старый адаптер Ramsey UUID. Подключайте его явно, если приложение ещё использует его: Identity больше не устанавливает этот пакет. |

## Что предоставляет пакет

- `UuidInterface`: минимальный контракт identity со string conversion и equality.
- `RfcUuidInterface`: UUID-контракт со свойствами `bytes`, `version`, `variant`.
- `Uuid`: иммутабельный RFC UUID-объект значения на базе 16 сырых байт.
- `UuidFactoryInterface`: контракт генерации и создания из bytes.
- `UuidFactory`: генератор UUID v1, v3, v4, v5, v6, v7 и v8.
- `UuidNamespace`: стандартные namespaces для name-based UUID.

## UUID Value Object

```php
use Componenta\Identity\Uuid;

$uuid = Uuid::fromString('018f6d5d-3f7a-7a9b-8c2f-123456789abc');

$uuid->toString(); // 018f6d5d-3f7a-7a9b-8c2f-123456789abc
$uuid->bytes;      // 16-byte binary representation
$uuid->version;    // 7
$uuid->variant;    // UuidVariant::Rfc
```

`Uuid::fromString()` принимает шестнадцатеричные цифры в верхнем, нижнем и смешанном регистре и возвращает каноническое представление в нижнем регистре. Для совместимости допускаются окружающие символы, удаляемые PHP-функцией `trim()`; при необходимости строгой проверки исходного строкового формата проверяйте его отдельно. Некорректное входное значение не копируется в текст исключения. Входные параметры разбора и нативного восстановления помечены `SensitiveParameter`: PHP скрывает их значения в кадрах трассировки библиотеки, даже если сохранение аргументов включено. Это не скрывает аргументы вызывающего кода, данные в журналах приложения или значения, явно извлечённые из `SensitiveParameterValue`. В production используйте `zend.exception_ignore_args=1` и не десериализуйте недоверенные данные.

## Equality

```php
$left = Uuid::fromString($id);
$right = Uuid::fromBytes($left->bytes);

$left->equals($right); // true
```

Доменный код обычно должен зависеть от `UuidInterface`. Инфраструктура, которой нужны raw bytes или inspection версии, может зависеть от `RfcUuidInterface`.

## UUID Factory

```php
use Componenta\Identity\UuidFactory;
use Componenta\Identity\UuidGenerationVersion;
use Componenta\Identity\UuidNamespace;

$factory = new UuidFactory(UuidGenerationVersion::V7);

$id = $factory->generate();              // версия по умолчанию
$random = $factory->v4();                // случайный UUID
$ordered = $factory->v7();               // UUID с Unix timestamp
$nameBased = $factory->v5(UuidNamespace::Dns, 'example.com');
```

Name-based UUIDs детерминированы для одного namespace и name.

## DI-регистрация

`ConfigProvider` регистрирует `UuidFactoryInterface` через фабрику, возвращающую `UuidFactory`.

## Генерация, безопасность и уникальность

UUIDv7 использует 12-битный счётчик со случайным начальным значением и новые 62 криптографически случайных бита для каждого идентификатора (RFC 9562, §§ 5.7 и 6.2, метод 1). Один экземпляр фабрики сохраняет порядок при повторе или уменьшении миллисекунды; переполнение счётчика увеличивает логическую временную отметку. Поэтому встроенная отметка может опережать системное время. Выход за диапазон времени приводит к `OverflowException`, а не к усечению. UUIDv1 использует случайный идентификатор узла с установленным битом групповой рассылки и случайное начальное значение последовательности; при откате физических часов последовательность изменяется, при клонировании фабрики или разветвлении процесса состояние создаётся заново. UUIDv6 получает новую 14-битную последовательность и новый случайный идентификатор узла для каждого UUID (RFC 9562, § 5.6). При отказе источника случайности ни одна из этих версий не расходует логическую временную отметку. Сериализация фабрики сохраняет настроенную версию по умолчанию, а не состояние генератора; прежние снимки фабрики восстанавливаются как новые генераторы.

Глобальная уникальность и порядок между независимыми фабриками или процессами не гарантируются. UUID не является секретом, токеном доступа или проверкой авторизации. Для случайных идентификаторов предпочтителен UUIDv4, для секретов — независимые криптографические токены. UUIDv3/v5 являются детерминированными форматами на основе имени, а не стойкими к коллизиям криптографическими хешами. Уникальность UUIDv8 зависит от входных полей. Если коллизии недопустимы, обеспечивайте проверку уникальности в хранилище. Нативная десериализация PHP предназначена только для доверенных данных; при восстановлении UUID проверяется согласованность его полей, а состояние создаётся из значений без сохранения ссылок из сериализованного графа. Формат корректных ранее сериализованных UUID сохраняется.

### Выбор версии UUID

Для новых упорядоченных по времени идентификаторов используйте UUIDv7, а если нежелательно раскрывать время и порядок создания — UUIDv4. RFC 9562, § 8 рекомендует UUIDv4, когда UUID необходим в операции, связанной с безопасностью; проверка прав доступа всё равно должна выполняться отдельно. Разбор UUID не подтверждает его подлинность и не позволяет обнаружить подмену. Для совместимости форматов на основе имени предпочтителен UUIDv5 вместо UUIDv3; оба не подходят для защиты от намеренно подбираемых коллизий. Если протокол требует более стойкого хеширования имени, необходимо отдельно определить формат UUIDv8, а не менять алгоритм UUIDv5.

Стандартная фабрика использует системные криптографические источники случайности PHP: `random_bytes()` и `random_int()`. Ошибки получения случайных данных распространяются без перехода на менее стойкий генератор. UUIDv4 содержит 122 случайных бита, UUIDv6 получает 61 новый случайный бит (последовательность и идентификатор узла), UUIDv7 — 62 новых случайных бита для каждого фиксированного сочетания времени и счётчика. UUIDv1 использует случайно инициализированное состояние узла и последовательности на экземпляр генератора, поэтому идентификаторы этого экземпляра могут быть связаны между собой. Вероятность коллизии зависит от версии, распределения префиксов, числа независимых генераторов и качества системной случайности. Фабрика не предназначена для повторного входа в процессе генерации или одновременного использования потоками без синхронизации. Она не координируется с другими процессами и не сохраняет рабочее состояние в постоянном хранилище.

Используйте UUID как непрозрачные идентификаторы. Встроенная временная отметка не является достоверным временем для аудита. Где возможно, храните 16-байтовое представление в нативном UUID-типе или двоичном поле базы данных, с ограничением уникальности при недопустимости повторов. Методы `Uuid::fromBytes()` и `Uuid::fromString()` представляют все 128-битные комбинации, включая Nil, Max и зарезервированные варианты; успешный разбор не означает, что значение сгенерировано одним из поддерживаемых алгоритмов. Четыре предопределённых пространства имён соответствуют RFC 9562; другие зарегистрированные или частные пространства имён можно передавать как объекты UUID. Для нового частного пространства имён генерируйте UUIDv4 или UUIDv7, не продолжайте последовательность выделения значений реестра IANA (RFC 9562, § 6.6). Не используйте зарезервированное для этих целей значение 6ba7b813-9dad-11d1-80b4-00c04fd430c8.

## Проверки при разработке

- `composer check` запускает PHPStan и обычные и детерминированные проверки контрактов на Pest 4.
- `composer stress` запускает выборочные проверки коллизий и монотонности, в том числе в реально разветвлённых процессах при наличии PCNTL.
- `composer test:negative` проверяет целевые сценарии RED/GREEN в изолированных копиях исходников. Требуется PCNTL.
- `XDEBUG_MODE=coverage composer test:mutation` запускает мутационную диагностику с Xdebug. Для дочерних процессов проверяется подстановка исходника и фактическое выполнение тестов; падения утверждений, ошибки тестов, выжившие, непокрытые и неподтверждённые мутации учитываются отдельно. Исходный процент Pest не является доказанной оценкой покрытия.

Подмены времени и энтропии подключаются только в специальных тестовых конфигурациях и вспомогательных сценариях, но не при рабочей автозагрузке библиотеки. Проверки разветвления процессов явно пропускаются на Windows. Подробности и ограничения приведены в [отчёте аудита](docs/audits/2026-11-25-identity-pest.md).

## Упорядоченное сравнение UUID

`ComparableUuidInterface` — необязательное расширение минимального контракта UUID. Стандартная реализация `Uuid` поддерживает его; ни `UuidInterface`, ни `RfcUuidInterface` не требуют реализации упорядоченного сравнения от существующих пользовательских классов.

~~~php
use Componenta\Identity\ComparableUuidInterface;
use Componenta\Identity\ComparisonResult;
use Componenta\Identity\Uuid;
use Componenta\Identity\UuidInterface;

$left = Uuid::fromString('018f6d5d-3f7a-7a9b-8c2f-123456789abc');
$right = Uuid::fromString('018f6d5d-3f7a-7a9b-8c2f-123456789abd');

$left->compareTo($right); // ComparisonResult::Less
$right->compareTo($left); // ComparisonResult::Greater
$left->compareTo($left);  // ComparisonResult::Equal

$values = [$right, $left];
usort($values, static fn (ComparableUuidInterface $a, UuidInterface $b): int => $a->compareTo($b)->value);
~~~

Перечисление результата имеет фиксированные целочисленные значения: Less = -1, Equal = 0, Greater = 1. UUID упорядочиваются лексикографически по 16 байтам в сетевом порядке (RFC 9562, § 6.11), что эквивалентно порядку беззнаковых 128-битных чисел. Второй операнд может быть любой корректной реализацией UUID: расширенный контракт предоставляет байты, минимальный — каноническую строку. Результат Equal согласован с `equals()` для UUID, соблюдающих контракт. Сравнение не извлекает время, не ограничивает версии/варианты, не преобразует бинарные строки в числа и не меняет формат нативной сериализации. Порядок значений не гарантирует хронологию создания, особенно для смешанных версий, UUIDv1 и независимых генераторов. Минимальный интерфейс фабрики по-прежнему возвращает `UuidInterface`; перед сравнением результата неизвестной реализации проверяйте `instanceof ComparableUuidInterface`. Упорядочивание не является операцией авторизации.
